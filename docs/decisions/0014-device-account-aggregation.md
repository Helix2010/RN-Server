# ADR-0014：设备、账号与版本信息的管理端聚合

状态：Accepted（2026-09-07）

## 背景

管理端需要看到每台设备上的账号、当前活跃的账号、App 的 APK 与 OTA 版本，同一设备上的账号要聚合，卸载重装归到同一设备，同一地址还可能在不同租户使用。核对现状：`app_installations.ota_revision` 存的是 bootstrap 下发的可用修订号而非运行中的版本；登录与安装实例的关联被设计成可选，线上 8 条会话 0 条关联；`wallet_user.status='blocked'` 登录时未校验；撤销安装实例不结束会话；会话无清理。完整设计在 RN-App `docs/design/device-account-aggregation-2026-09-07.md`。

## 决策

- **版本信息由心跳显式上报**：新增 `launch_source ENUM('embedded','ota')` 与 `running_update_id`，`running_ota_revision` 由服务端关联 `ota_releases.update_id` 得到；旧版未上报存 NULL 并在管理端显示"未上报"，关联不上显示"未知更新"，不猜。`ota_revision` 保留为"可用修订号"，两者之差即待生效。
- **账号关联以登录为准，且必须关联**：`/v1/mobile/auth/verify` 必带安装凭证，失效时 App 重新注册后重试一次，再失败返回 `INSTALLATION_REQUIRED`。心跳不上报账号（客户端不可信）。
- **当前账号从会话派生**：签发会话时在同一事务把同安装实例的旧有效会话标 `superseded`，保证一个安装实例同一时刻最多一条有效会话；不在 `app_installations` 加冗余列。新增 `wallet_session.ended_reason` 与按安装实例的索引。
- **先复用再建表**：账号、会话、安装实例、设备归并全部复用；只新增 `wallet_user_installation`（登录历史汇总，登录时同事务写）与 `platform_wallet_block`（平台级封禁）。
- **封禁两级**：租户级用现有 `wallet_user.status`，平台级新表；登录时先平台后租户，命中 403 并结束会话；App 显示明确原因。撤销安装实例同时结束其会话。
- **跨租户仅平台管理员**：租户接口永不返回 `device_client_id`；平台接口按完整地址或设备查询，逐次写审计；跨租户设备聚合依赖各租户正式包共用签名密钥，签名切换日设备归并重置一次（切换前历史留在安装实例与汇总表）。
- **保留**：会话、汇总表、封禁表都永久保留，不做自动清理（用户决定）；过期在读取时按 `expires_at` 判断。
- **心跳对账字段**：`client_session_state`（signed_in / signed_out）随心跳上报，只与 `wallet_session` 比对并在管理端标出差异，不参与判定。

## 替代方案

- 心跳上报账号列表：客户端可伪造、与服务端会话不一致时无从裁决；否决，保留可选的对账字段（只展示差异）。
- `app_installations.current_user_id` 冗余列：登录 / 登出 / 过期 / 撤销 / 封禁五条路径都要维护，必然漂移；否决。
- 全局用户表合并跨租户账号：资产与代理钱包按租户隔离，合并没有业务含义且扩大泄露面；否决，仅按 `address_key` 识别。

## 安全边界

- 设备标识仅 HMAC 存储，不用于任何安全判定。
- "某地址在哪些租户使用"视为敏感信息：仅平台管理员、完整地址、逐次审计、不提供批量导出。
- 封禁、撤销会话、撤销安装实例都要求原因与确认并写 `audit_events`。

## 已决（用户 2026-09-07）

- 登录必须关联安装，安装注册不可用时登录失败并显示 `INSTALLATION_REQUIRED`。
- 会话数据永久保留。
- 心跳对账字段实施，字段在一期、差异展示在二期。
- 租户管理员可见本租户内同设备的其他安装实例；封禁立即结束现有会话。
