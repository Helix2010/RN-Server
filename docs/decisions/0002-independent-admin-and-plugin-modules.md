# ADR-0002：独立管理前端与可插拔平台模块

- 状态：Accepted for foundation
- 日期：2026-08-24

## 背景

发布、配置、灰度、审计属于运营控制面，不应和 RN-App 的移动端导航、原生构建或升级周期绑定。后续多个 DEX/Web3 项目需要复用同一套发布能力，但业务页面、品牌和权限又会不同。

## 决策

建立独立 `/Users/Amos/work/RN-Admin` Web 管理前端。RN-Server 负责可复用的管理 API 和领域规则，RN-Admin 只负责桌面端交互、权限呈现和插件装配。每个管理能力以 `AdminPlugin` 注册：插件声明 id、导航、页面和所需权限；宿主只依赖协议，不依赖具体业务模块。

首期插件：

- `release-management`：总览、发布列表、状态动作；
- `app-config`：语言、主题、Feature Flag、升级策略的查看、校验与编辑；
- `audit`：发布操作审计。

## 为什么不放进 RN-App

- 发布管理员需要桌面宽屏的表格、筛选、批量和审计能力；
- 管理端生命周期独立于移动端商店/直分发/MDM 升级；
- 一个管理端可以连接多个 RN-Server 项目；
- 管理模块可以按项目注册/卸载，不增加移动包体和原生权限；
- 移动端不能成为高权限发布控制面，降低误操作与越权风险。

## 安全边界

当前服务端提供开发用 `x-admin-key` 适配器，仅用于本地闭环，并使用 MySQL 持久化审计。按当前阶段范围暂不加入 RBAC 和双人审批；未来可替换为 OIDC/JWT 与权限插件。管理 UI 的按钮不能替代服务端状态机。Artifact 的上传、签名校验、短时下载 URL、对象存储和 telemetry 仍是生产化阶段的独立任务。

## 后果与退出策略

前端仓库增加一次部署和域名治理，但避免移动端与运营控制面相互阻塞。插件契约保持小而稳定；当某模块拥有独立团队、数据所有权或扩缩容证据时，可以把 RN-Server 模块拆成服务，RN-Admin 插件 API 不变。
