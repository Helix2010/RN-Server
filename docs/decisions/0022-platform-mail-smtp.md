# ADR-0022：平台发信（SMTP），用于统一登录的绑定验证码

状态：Accepted（2026-09-26）

表与配置：`docs/database/ADMIN_ACCOUNTS_SCHEMA.md`（`app_configs` 平台级 `mail.smtp`）；接口：`contracts/openapi.json`；上下文：ADR-0021。

## 背景

用户 2026-09-26 决定：统一登录的绑定要先给统一认证账号的邮箱发验证码，能收到这个邮箱的信才能绑上。起因是浏览器里残留别人的认证中心登录态时，单点登录不再问口令，确认页虽然显示邮箱，人可能不看就点了。pm 商户后台同日上了同样的做法。

RN-Server 此前没有发信能力。pm 的发信是嵌在 tenant-service / platform-service 进程里的代码，没有对外接口。用户选择 RN 自带发信模块，不给 pm 加内部发信接口：那样 RN 要依赖 pm 的可用性、要做服务间鉴权，而且 pm 的 SMTP 配置按 pm 租户存，和 RN 租户对不上。

## 决策

1. **新包 `internal/mail`**，只用标准库 `net/smtp`，不引入新依赖。它是适配器，只管连接、认证、投递；发件账号的保存与邮件内容在调用方。
2. **传输安全**：
   - 465 端口走隐式 TLS，其它端口必须 STARTTLS；
   - 只有本机地址允许明文，给本地调试的假 SMTP 用；
   - 不为「对方不支持 TLS」退回明文：验证码与账号口令都不该明文过网。
3. **发件账号是平台级一份**：放 `app_configs`（`tenant_id=0`，键 `mail.smtp`），口令用 `secretbox` 加密（AAD `mail-smtp:password`），不经任何接口返回。
   - 由平台管理员在控制台「平台维护 › 邮件发送」保存，写入时校验，要填 reason，写 `audit_events`；
   - 保存后可以发一封测试邮件确认；
   - 口令留空表示沿用，但服务器、端口、用户名任一项变了就必须重填（422 `MAIL_PASSWORD_REQUIRED`）：否则改个地址再试发，旧口令就会被送到别的服务器。
4. **没配发信就不能完成绑定**：返回 503 `MAIL_NOT_CONFIGURED`，不退回「不校验」（AGENTS.md「不写回退」）。
5. **绑定验证码**：
   - 只属于「这个账号 + 这个统一认证账号」；10 分钟有效，用一次就作废，输错 5 次作废；
   - 放在进程内存里：RN-Server 单实例，重启后重发即可；
   - 限流：同一账号 1 分钟 1 次、1 小时 5 次，同一 IP 1 小时 20 次。每小时的配额按尝试计；1 分钟的间隔只在投递成功后开始；
   - 投递成功才换上新码，失败时邮箱里已有的旧码继续有效；
   - 待确认绑定的 Cookie 从 5 分钟延长到 10 分钟，和验证码一样长。
6. **认证中心没给邮箱的统一认证账号不能绑定**（`no_email`）。
   - 查过认证中心源码：管理接口与自助注册建的账号都必有邮箱；
   - 真库只有 2 个历史遗留账号没有邮箱。
7. **不回显对方服务器的原话**：发信失败按种类返回固定的 Problem（`MAIL_CONNECT_FAILED` / `MAIL_TLS_FAILED` / `MAIL_AUTH_FAILED` / `MAIL_REJECTED` / `MAIL_SEND_FAILED`）；原始错误只进日志。审计里收件人掩码，不含验证码。

## 后果

- 上线前平台管理员要先配好发信，否则成员绑定不了。
- 防得住「绑错账号」，防不住「会话被盗后绑到攻击者自己的统一认证账号」：验证码会发到攻击者自己的邮箱。
- 以后有别的发信需求（通知、找回口令）复用同一个包与同一份配置。

## 回滚

还原提交即可。`app_configs` 里的 `mail.smtp` 留着无害；要删，就在控制台删掉，或删掉这一行。
